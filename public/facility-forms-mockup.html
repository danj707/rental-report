Facility rentals · design decision

Rental forms on the schedule

Three ways to put form answers on a rental, mocked at real density with Watertown's real submissions — so the choice can be made by looking rather than by imagining.

Recommendation: ship B, with A as a column toggle

B — chips in the row, answers inline on click. The row keeps one line and carries only the answers that change what staff do; clicking opens the full Q&A in place. This is the default because 98% of Watertown's rentals carry two forms and 9 answers, and because only a handful of those answers are ever actionable.

A — the always-on inline sub-row — is worth having, but as a toggle, not a default. It's the treatment a parks crew wants on paper, and the report already has the mechanism (.sub-row, used today for Notes and Add-Ons). But it triples the height of a day section, and it cannot survive the 1.4 KB answer further down this page. So: a Show answers checkbox beside the existing column toggles, off by default, honoured by Print and PDF.

The one thing I would not do is a column per question. Watertown's rentals draw on 9 different forms with disjoint question sets — that's roughly 40 columns at 38% fill for one week, and a waiver's question is 3,257 characters long, so it can't be a column header at any width. That's why the Programs pulldown doesn't transfer: a roster has one form per section, and this doesn't.

Inline sub-row, always on

Every answer printed under its rental, no interaction, reusing the mono sub-row the report already uses for Notes. This is the literal reading of “show the questions and answers inline” — and the point of mocking it at full density is that you can see exactly where it stops working.

Works

Breaks
Five rentals became eleven lines. Across the 47-rental week that's a document roughly 2.5× longer, and the exceptions — one grill, one catered — are now buried in prose rather than standing out. The three unremarkable rentals cost as much vertical space as the one that needs attention.
Fails
The 1.4 KB pasted schedule further down this page. There is no compression of that answer that fits a table row.

The rule that keeps the column quiet: chip the exception, not the norm

484 of 485 picnic rentals uploaded an ID, and 484 signed the waiver. A chip on every row is decoration, so “ID on file” and “waiver signed” collapse into one grey ✓ 2 forms and only their absence goes loud. Grill (39%), catered (5%), public (4%) and a head-count mismatch (15%) are common enough to be worth scanning and rare enough to stand out.

Option C

Chips only — full form on the posting sheet

Same row as B, but no expansion at all: the answers live on the permit posting sheet instead. Worth naming because lib/permit.js already prints one page per rental and hangs at the facility, and grill / attendees / catered is precisely what a crew standing at a pavilion needs. It is the right print home for the detail regardless of which option wins — but it can't be the only one, because the office staff answering the phone need the answers on screen, and not every rental has a permit.

My read: not an alternative to B, an addition to it. Ship B, then put the same answers on the sheet.

Whichever option wins

Five things in this data that will break a naive renderer

01

Answers are keyed by machine name — the schema join is mandatory

Every question on the field application is named question1…question9, and the picnic form's question2 is silently “Grill Request”. Without the form's schema the answers are unreadable.

Raw submission: {"question2": false, "question1": [file]} — render title ?? name, and never print a bare questionN.
02

false is an answer, not a blank

Truthiness-filtering “empty” answers deletes every No — including the 295 rentals that explicitly did not want a grill.

Booleans: 485 answered, 0 blank, 2 distinct values. Filter on undefined, never on falsy.
03

Choice answers are opaque values needing the schema's map

The waiver's answer is ["Item 1"], not “I Agree”. The field form's ["Item 5"] means “Watertown Youth Organization”. Values are arbitrary and unordered — Item 4 is listed first — so position can't infer them.

Map through choices[].value → choices[].text, or you ship “Item 1” to a parks crew.
04

The same key is a file array in one form and a string in another

question1 holds two driver's-licence images on the picnic form and the text “Watertown Youth Soccer” on the field form. A renderer keyed on names without types throws — the exact shape of the blank-page bugs already in this repo.

A probe query hit it immediately: ERROR: cannot get array length of a scalar. Branch on the schema's type, not the key.
05

Uploaded files can't be shown — the bucket refuses us

The submission carries a direct S3 URL, so it looks displayable. It isn't: fetching it returns 403 AccessDenied. An inline preview would be a broken image on essentially every picnic row, so files render as a name-and-size chip linking into Rec admin.

Verified: curl → status=403, content-type=application/xml. There is no signing path in this app.
To build it

What it costs

  • One new card column, not a new card. Card 17294 gains a Forms JSON array — the shape the roster card already emits, but an array, since a rental averages 2.08 forms. No new query, no second round trip.
  • Watch the multi-day expansion. 17294 emits one row per day via generate_series, so a 40-date permit would repeat the same form JSON forty times. Emit it on the arrival day only — the rule dirOutdoor and the permit sheet already use.
  • A blank Requests cell is legitimately blank. Only 1 of 1,137 requested forms at Watertown is outstanding, so “no form” means none was ever asked for — not a to-do. No red state for absence, or the column cries wolf on 62% of rows.
  • It generalises. Rental forms are in use at 93 orgs — Sacramento County 660 rentals, Rocklin 585, Watertown 546, Windham 532, Menifee 414. This isn't a Watertown feature.
Three calls I'd want from you

1 · Does the ID upload belong in exports? The chip is safe; the filenames are not neutral — one is literally JPM_Driver_s_License_back_2023-2028…jpg. This report is shared by tokened link, exported to Excel and mailed by subscription, so surfacing filenames changes what it distributes. My recommendation: chip on screen, filename only in the expanded panel, nothing in Excel or email.

2 · Auto-derive chips, or curate per org? Auto-derivation covers all 93 orgs with no config — a boolean answered yes becomes a chip, a file becomes 📎, long text becomes 📝. Curated labels read better (“Grill” beats “Grill Request”) but only where someone has done the work. I'd ship auto-derived with an optional override.

3 · Is the count mismatch a chip or a footnote? It fires on 15% of rentals — often enough that some staff will read it as noise, and it may just mean the party grew since booking. Chip it and it gets acted on; bury it and the pavilion is set for 30 when 45 arrive.

And it ships with a Slack ping
