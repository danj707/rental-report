🔧 The Metabase card change (what to build tonight)
  • Union a second source into the court-utilization card: program/lesson session rows whose location resolves to a court — same output shape (location_name, court_name, site_type, id, booking_source, purpose, local_date, duration_hours).
  • Stamp usage_category (the column already exists in the feed, currently empty): instant · lesson (marketplace instructor sections) · permit_program (managed reservations) · closure (purpose = "Unavailable"/"Closed"). The report's closure bucket is already wired to this column and starts working the moment it's populated.
  • Lesson detection: section belongs to the lessons marketplace (instructor-linked section; fallback heuristic program_name ILIKE '%lesson%'), booked sessions only (booking.status = confirmed).
  • No breaking change: existing rows keep booking_source as-is; the report falls back to today's instant/managed split when usage_category is null — old cached rows stay valid.
  • After the card edit: same UUID keeps all wiring; re-flip the Start/End Date variables to type Date in the Metabase UI (the usual reset), then verify with a parameterized request.
