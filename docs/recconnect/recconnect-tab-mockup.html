This tab compares one eligibility group against everyone else. The cohort is every person on an active Free Lunch Program membership — Norman's income-qualified group, standing in for RecConnect while Reno is not yet live. Check-ins are attributed through the membership that was scanned, so a visit counts against the cohort only if the member used it. The comparison is every other active member, not a full-pay cohort: 6,371 of the 12,508 hold only $0 memberships (free residency), so this contrasts one subsidy against a mixed base rather than against people paying list price.
Cohort membership is resolved through both coverage shapes — household-coverage groups by household, individual-coverage groups by named member. Reno's own ladder mixes the two, and a household-only query returns zero for the individual tiers without erroring.

The headline is the third row. A subsidy sceptic assumes discounted members either don't show up or over-consume. Neither is true here: they activate at nearly twice the rate, and then use the facility at the same intensity as the membership base as a whole. That is the sentence for a council slide.

How it is built

  • Cohort = a group. membership.group_id → group.group_type = 'special-group'. No new concept — RecConnect is already four groups in Reno's sandbox.
  • Resolve the member both ways. COALESCE(membership_user.user_id, users.id via household_id). Household-coverage rows carry household_id; individual-coverage rows carry NULL there and link through membership_user.
  • Usage joins directly. attendance_event.check_in_method_id → membership.id → group. Measured at Norman: 46,857 of 46,857 membership-method check-ins resolve to their group. No inference.
  • No card change for the cohort itself — but this is a new card, because card 17301 is purchase-grain and has nowhere to put a comparison cohort.
  • Base tables, not materialized. Every query behind this page ran in 0.3–2.5s.

What would make it wrong

  • Selection, not causation. 97.9% activation is partly that people enrol in these programmes at a facility. The tab must say so, and the honest claim is the intensity index — 0.98× — which has no such bias.
  • Household-only cohorting returns zero silently. All 188 Norman rows have household_id NULL. It looks like an unused programme, not a bug.
  • Small cohorts. A tier with six members cut by hour and weekday describes identifiable families. Suppress percentages under a floor — the RATE_MIN_VIEWS rule.
  • Presence-gate the tab. An org with no special-group shows nothing, never a confident zero.
  • Reno is not live. Every figure here is Norman's, named as such. Nothing on this page is Reno data.
